# JD 证据型简历制作

根据目标岗位 JD，通过逐轮提问核实求职经历，选择最能证明岗位能力的证据，制作可编辑 Word 和可投递 PDF 简历。

**核心流程：读 JD → 核实经历 → 筛选证据 → 表达岗位能力与软技能 → 制作和检查文件。**

## 适合谁

- 有目标岗位，希望简历紧贴具体工作职责的求职者。
- 有课程、小组、个人项目或实习经历，但不清楚如何表达岗位能力的应届生。
- 有工作经验，需要为新岗位重新选材、突出个人贡献的求职者。
- 已有简历，需要根据另一份 JD 调整内容的人。

支持不同岗位和行业，不预设求职者的姓名、学历、经历或工具水平。它是一套 AI 工作流程，不是固定的简历填空模板。

## 它会怎么做

1. 阅读 JD，将实际职责、必要资格、偏好项和软技能分开。
2. 复用已经确认的信息，默认每轮问一个最影响判断的问题。
3. 核实本人负责什么、用了什么方法、交付了什么，以及结果是否真实发生。
4. 选择最相关、证据最充分的经历，把具体行动写成岗位能力。
5. 用真实行为体现学习、协作、执行、严谨等软技能。
6. 事实齐全后制作 DOCX 和 PDF，核对内容并查看全部页面。

用户要求“有 95% 把握再开始”时，按关键事实是否齐全来判断，不声称计算了匹配率或录用概率。已有完整资料时不会为了提问而反复盘问；小范围修改不会重启整套问卷。

## 安装到 Codex

下载或克隆这个仓库，保留完整目录，文件夹命名为 `jd-evidence-resume`。个人使用可放在：

```text
~/.agents/skills/jd-evidence-resume/
├── SKILL.md
├── README.md
├── agents/openai.yaml
└── references/
```

只供某个项目使用时，可放在项目的 `.agents/skills/jd-evidence-resume/` 中。已有同名技能时更新现有目录，避免在多个位置安装重复版本。

Codex 的 `$skill-installer` 也支持从其他 GitHub 仓库安装。安装后确认技能列表中可见 `jd-evidence-resume`；若没有显示，按官方说明重启 Codex 再检查。

安装位置与发现机制参考 [OpenAI 官方技能文档](https://learn.chatgpt.com/docs/build-skills)。其他兼容 Agent Skills 的环境，请按该环境的安装和调用方式使用；本项目目前的完整文件测试在 Codex 环境中完成。

## 快速开始

安装后，在 Codex 中输入：

```text
$jd-evidence-resume

请根据下面的岗位 JD 为我制作简历。
先逐轮问问题，核实我实际做过什么，选择最能体现岗位能力的经历。
软技能也用具体行为支撑，最终交付可编辑 Word 和可投递 PDF。

目标岗位：独立站运营助理
JD：在这里粘贴职位描述，或附上清晰截图／链接。
已有资料：附上已有简历、项目报告或作品；没有也可以先描述经历。
```

能读取材料时，会先从原文寻找证据，再问仍然缺失的事实。信息不清楚就如实说明，不要求求职者为了匹配而编造经历。

## 使用示例

### 有课程项目，没有正式工作经历

```text
请使用 $jd-evidence-resume。
我想投市场研究助理，做过课程营销企划和小组问卷分析。
请先问清我的个人贡献、数据来源和实际产出，再决定哪些经历值得写。
```

预期：核实项目内容，将相关行动对应到研究、分析和协作；保留课程项目性质，不增加商业落地结果。

### 已有简历，要换目标岗位

```text
请使用 $jd-evidence-resume，根据新的品牌管培生 JD 调整附件简历。
已经明确的信息沿用，只追问影响本次选材和真实性的缺口。
突出用户理解、产品价值和经营判断，最后更新 Word 和 PDF。
```

预期：重新判断 JD 匹配和经历优先级，而非把原有经历全部保留或只替换关键词。

### 只修改已经确认的一处内容

```text
请使用 $jd-evidence-resume。
把附件简历中的“精通 Excel”改为“Excel 公式计算与数据核对”。
其余内容保留，检查版式并更新同版 PDF。
```

预期：直接完成授权的小修改，检查受影响内容，不重新询问全部背景。

## 运行条件

GitHub 用于保存和分享技能文件，实际工作在使用者的 AI 环境中进行。这个技能不内置模型、API 密钥、文档转换器、字体或服务器，也不会自行安装全部依赖。

| 能力 | 需要的环境支持 |
|---|---|
| 按技能完成访谈和写作 | 能加载 `SKILL.md`、阅读引用文件并与用户多轮对话的 AI 助手 |
| 阅读材料 | 文件读取工具；截图需图像理解或 OCR；PDF／Word 需相应读取工具 |
| 创建可编辑 Word | 可用的文档工具；Python 方案通常使用 `python-docx` |
| 创建同版 PDF | DOCX 转 PDF 工具，例如 LibreOffice 或运行环境提供的转换器 |
| 检查版式 | PDF 页面渲染工具与能够查看生成图片的能力 |
| 检查文本和链接 | PDF／DOCX 读取工具；Python 方案可使用 `pypdf` 和 `python-docx` |
| 中文正常显示 | 能用于生成和渲染的中文字体 |
| 阅读在线 JD／作品 | 可用的网页访问工具；仅处理本地材料时不必启用 |

优先使用环境中可用的 `documents`、`pdf` 技能或等效工具。在具备工作区依赖发现功能的 Codex 桌面环境中，助手可以先发现运行时和库；其他环境需提供等效能力。

技能说明了制作方法，但本仓库不附独立运行的简历生成程序。缺少生成或视觉检查能力时，助手应说明限制和已完成部分，不能只返回文字就称已交付 Word／PDF，也不能把转换成功当作版式检查通过。

## 最终交付

- 可编辑的 `.docx`。
- 与 Word 内容一致、文字可选择的 `.pdf`。
- 简短说明本次重点呈现的能力，以及影响投递的重要资格缺口。

应届／初级岗位默认简洁一页；资历丰富或用户有其他要求时适当调整。照片可选，版式优先遵循已有模板或用户要求。已确认的作品与邮件链接应保留点击功能。

## 表达与使用边界

- 课程企划、商业模拟、个人实践、实习和正式工作分别标注。
- 规划、预测和建议不写成已经发生的销售、投放或增长。
- 团队项目写清本人贡献；教师提供的数据不写成自己采集。
- 基础练习不写成熟练实战；没有数字也可以用真实交付说明成果。
- 软技能通过具体行动体现，不堆泛泛的自我评价。
- 不自动联系 HR、投递简历、修改求职平台档案或公开求职者资料。

本仓库的示例采用通用场景，不包含真实求职者的身份或项目文件。公开仓库中只放技能文件；实际简历、报告、联系方式及对话记录保留在使用者自己的授权环境中。

## 已验证的范围

完成过五个行为场景测试，覆盖首轮提问、数据来源、模拟与真实经验、已授权的小修订和未完成检查时的交付说明。另用合成求职资料完成了一页 DOCX／PDF 制作测试，检查了文字一致性、可编辑性、可选择文字、邮件链接及全页版式。

这些测试验证流程的执行情况；新 JD、求职者事实和不同运行环境仍需在使用时核实。
